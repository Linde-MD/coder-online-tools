# API 规范

## 模块接口

- 模块对外暴露的函数、对象和返回值必须稳定、明确。
- 模块边界要显式，不要依赖隐式全局状态或魔法字段。

## 数据边界

- 请求、持久化、协议转换、数据适配应集中在 service、infra、domain 或 utils。
- UI 层不要直接承担数据解析、存储或协议细节。
- 导入数据必须校验文件类型、大小、结构和字段范围；外部 API 的请求/响应需在边界处验证并归一化。
- 前端代码和构建环境变量均可公开读取，不得包含密钥。向第三方服务发送用户数据前须告知用途并取得授权。
- 不可信内容默认按文本处理；确需渲染 HTML 时，必须采用项目已有的隔离/净化方案，不得直接执行不可信脚本。

## 错误处理

- 错误处理方式要统一，不要在不同层级重复实现同一种提示逻辑。
- 失败路径必须可预测，不能静默吞错。
- 异步和外部调用的失败必须保留可诊断信息并向用户提供适当反馈；不得返回成功形状的默认值掩盖失败。
