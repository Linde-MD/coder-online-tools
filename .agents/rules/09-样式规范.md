# 样式规范

## 设计依据与边界

- [DESIGN.md](../../DESIGN.md) 保留通用视觉规范和原始参考，不记录仓库实现细节；本文件规定其在本项目的适配与实现方式。旧页面的不一致不是可复制的设计依据。
- 应用外壳统一暖米色画布、珊瑚色强调和平面工程工作区；不得新增独立主题、外部品牌要求或营销站布局。
- 业务图表、用户配色、语法高亮、古书输出和 iframe 内容保留自身语义；只统一外层界面，不通过全局覆盖改变内容。
- 修改涉及的旧界面渐进迁移，不做无关的全站样式重构。

## 技术与作用域

- 布局、间距、响应式优先 Tailwind；视觉属性消费共享 token。组件 CSS 使用 scoped 或 feature 前缀，跨模块视觉定义放共享层。
- 已有 Bootstrap 风格类仅兼容，不增加依赖、不扩展使用范围。兼容别名必须接入实际被消费者读取的主题变量，不能把未被消费的 `--bs-btn-*` 当作已生效。
- 禁止新增与 Tailwind 同名的手写工具类。同一元素同一属性不得由 Tailwind、旧工具类和兼容类竞争控制；不可假设旧 `.gap-8`、`.mb-4` 具有 Tailwind 语义。
- 不新增全局元素选择器或 `.card`、`.btn` 等宽泛覆盖来修复局部界面；不得向大型全局样式文件继续堆积 feature 专用规则。
- 不依赖导入顺序、不断提高选择器权重、`!important` 或 z-index 掩盖根因。

## 主题与组件

- 同语义 token 只保留一个值来源；颜色、字体、圆角和层级不得在 feature 中各复制一套。设计文档中的 YAML token 是设计记法，使用前必须确认对应运行时变量已定义并接入，不能当作现有变量使用。
- 品牌、动作和状态颜色分离：进入/保存等主要操作不因旧成功类名变绿；成功、警告、错误须有文字反馈。
- 展示标题使用共享衬线字体；面板、表单和操作使用共享无衬线；代码/数值使用等宽字体。保留中文与离线回退，禁止引入品牌专用字体。
- 本项目沿用 `--font-display`（Fraunces）、`--font-body`（Manrope）和 `--font-code`（JetBrains Mono）；设计参考中的品牌、字体名称和营销组件不要求照搬。
- 统一 4px 间距基准、控件 8px 圆角、面板 12px 圆角；标准控件高 40px、紧凑控件高 32px。同组操作保持一致密度。
- 默认实底加细边框，阴影限必要浮层；不叠加渐变、大投影和卡片上浮等装饰。图标优先本地 SVG，保持尺寸、线宽、配色和可访问性一致。

## 状态与可访问性

- 控件必须具有适用的 hover、focus-visible、pressed/selected、disabled、loading 和 error 状态；选中、错误不能只靠颜色或布局差异表达。
- 保留清晰键盘焦点，不得无替代移除 outline；普通文字对比度至少 4.5:1，大文字和必要非文本信息至少 3:1。浅品牌色不能默认用于白字小按钮。
- 纯图标按钮有可访问名称；触屏主要操作目标至少 44×44px。动画遵循减少动态效果偏好，不使用 `transition: all`。

## 布局与验收

- 本项目采用紧凑工程工作区：面板内边距 16–24px、内容页最大宽度约 1220px、多面板工作区约 1680px或满宽；不强制套用参考中的 96px 营销分区。
- 页面不得因卡片、导航或长内容产生非预期横向溢出；表格/代码/画布局部滚动，窄屏按可用空间折叠，禁止靠缩小文字塞入。
- 满高工作区通过共享布局/实际导航高度计算；不得复制 58/112px 扣减。导航下放大与 Fullscreen API 全屏模式必须分别正确处理。
- 层级按普通内容、导航、放大区、菜单、模态和通知的职责集中管理；局部浮层先检查 stacking context 和挂载位置，不随意增加全局高层级。
- 实际样式修改后验证桌面/窄屏、长文本、键盘、状态、滚动、浮层和涉及的全屏模式；公共样式修改同时执行现有构建和相关测试。未浏览器验证的结果不得宣称已完成视觉验收。
