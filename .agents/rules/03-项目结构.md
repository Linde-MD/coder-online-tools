# 项目结构

## 目录边界

- app：应用入口、路由挂载、全局编排。
- features：按业务能力拆分的功能模块。
- shared：跨 feature 可复用的组件、配置、工具和样式。
- styles：全局样式与基础主题。
- scripts：独立脚本、转换器、服务端脚本。
- tests：测试文件。

## 放置规则

- 页面和复杂业务优先放入对应 feature，而不是堆在页面壳里。
- 公共 UI 放 shared，业务专用 UI 放 feature。
- 数据处理、转换、持久化和协议逻辑优先下沉到 services、infra、domain 或 utils。

## 结构约束

- 不要随意新增新的顶层目录。
- 不要让 UI、业务逻辑和持久化逻辑互相混杂在同一个文件里。
