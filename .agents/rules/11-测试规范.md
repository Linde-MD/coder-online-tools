# 测试规范

## 基础要求

- 关键业务逻辑、规则计算、数据转换和复杂状态切换应有测试覆盖。
- 修复 bug 时优先补回归测试，避免只改表面行为。
- 测试使用项目现有 Vitest 配置、npm 脚本和目录组织；不得另建重复测试工具链。

## 覆盖边界

- 测试优先覆盖可回归、可验证的核心行为。
- 不要把所有测试都堆在 UI 层，业务逻辑应尽量下沉后测试。

## 质量门禁

- 新增功能不得引入明显的回归风险。
- 关键变更应能通过既有测试或新增测试验证。
- UI 改动需覆盖核心流程、窄屏、键盘操作和空/错误状态；持久化及导入导出需验证恢复或数据往返。
- 交付时只报告实际运行的命令与结果；未执行的浏览器、构建或部署验证须明确标注。
